1. Overview
This document explains how to call the SkyNav APIs available in the uploaded Postman collection. It is written for 
customers, support teams, and developers who need a clear understanding of the request method, required parameters, 
authorization, expected output, and common issues.

Important: The uploaded collection has a written description mentioning GET for device data, but the actual Postman request
method is POST. This documentation follows the actual request method configured in the collection.
2. Authentication and Common Request Rules
Each API request uses a bearer authorization token and form-data credentials. The token and password values must be 
kept private and should not be hard-coded in frontend applications.

Postman Setup
1. Select request method as POST.
2. Open the Authorization tab, choose Bearer Token, and enter the token value.
3. Open the Body tab, choose form-data, and add username, password, projectId, and companyName.
4. Pass query parameters in the URL, such as imei, start_datetime, and end_datetime.
5. Click Send and verify that the response content type is JSON.

5. Response Field Guide
The live device data response contains many fields. The table below explains the commonly used fields for application 
integration.
Field Meaning Usage
Vehicle_Name Display name of the vehicle/device. Show vehicle name in dashboard.
Vehicle_No Registered vehicle number. Vehicle identification and search.
Imeino Device IMEI number. Device mapping and API filtering.
Latitude / Longitude Current GPS coordinates. Show marker on map.
Speed Current vehicle speed. Movement/status display.
Status Vehicle/device operational status. Running/stopped/idle status logic.
GPSActualTime GPS packet time from the device. Use for last GPS update time.
Datetime Processed date-time value from API. Use for reports and display.
Location Resolved address or location string. Show user-readable place name.
IGN Ignition status. Determine vehicle ON/OFF.
AC AC status where applicable. Optional vehicle telemetry.
Odometer Odometer reading. Distance tracking and reports.
Fuel Fuel data array if available. Fuel analytics when supported.
battery_percentage Device battery percentage. Device health monitoring.
ExternalVolt External voltage value. Power monitoring.
6. Error Handling and Troubleshooting
HTTP Status / Issue Meaning Recommended Action
200 OK with JSON Request successful. Parse the JSON response and validate 
expected fields.
200 OK but empty response API accepted the request but returned no 
data, or upstream response is empty.
Check IMEI, date range, credentials, 
config/project mapping, and cURL errors.
400 Bad Request Required parameter missing or invalid. Verify imei, start_datetime, end_datetime, 
and body fields.
401 Unauthorized Authorization header missing or invalid. Send Authorization: Bearer 
<BEARER_TOKEN>.
403 Forbidden / Access Denied Server understood request but rejected 
authorization.
Check token validity, account access, 
project/company mapping, and endpoint 
permission.
500 Internal Server Error Server-side issue or integration code 
error.
Enable server error logs, check missing 
semicolons/undefined variables, and 
inspect cURL response.
Common Integration Mistakes
 Sending raw JSON body while backend code expects form-data or $_POST.
 Missing semicolon or undefined variables in PHP integration code.
 Using an expired or incorrect bearer token.
 Passing date-time with spaces that are not URL encoded.
 Using the wrong HTTP method compared with the configured endpoint.
 Forgetting that multiple IMEI numbers must be comma-separated without extra spaces.
 Logging or exposing real passwords, tokens, or IMEI values in public documentation or frontend code.

7. Developer Checklist
6. Confirm the base URL is https://api.skynavgps.com/v2.
7. Use POST for both APIs as configured in the Postman collection.
8. Pass Authorization as Bearer token.
9. Pass username, password, projectId, and companyName as form-data.
10. Pass imei as a query parameter. For multiple devices, use comma-separated IMEI values.
11. For history, pass start_datetime and end_datetime in DD-MM-YYYY HH:mm:ss format.
12. URL encode date-time spaces when calling the API outside Postman.
13. Do not expose tokens, passwords, or IMEI numbers in frontend code or user-facing logs.
14. Handle 200-empty, 401, 403, and 500 responses clearly in the application.
15. Validate the exact response schema with live API output before final deployment.
